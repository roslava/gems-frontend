## Формирование URL

Единственная функция imageUrl формирует
{VITE_CDN_BASE_URL}/entities/{storage_key}/images/{path}.
Сохраняются исходный storage_key, кодирование сегментов и проверки относительного пути.
Карточки, страницы минералов, галереи и полноэкранный просмотр используют эту функцию.
Абсолютные URL статей не переписываются, включая исторические ссылки.
BlockRenderer уже использовал ссылки напрямую для обычных, парных и локализованных
изображений; менять его не потребовалось. В Markdown добавлены img/src/alt в
разрешённые DOMPurify элементы и атрибуты, чтобы контентные изображения не удалялись.

## Обложки

Публичный endpoint: /api/v1/posts/{slug}/cover-frames?lang=ru|en.
Формат подтверждён чтением локального API: frames: [{index, url}].
Порядок ответа сохраняется без сортировки и генерации имён.
В покое карточка показывает первый загруженный кадр; fallback — cover_image,
затем прежний placeholder. Hover запускает цикл с интервалом 700 мс.
Следующий кадр предварительно загружается; текущий остаётся до готовности следующего.
Ошибочные кадры пропускаются, загрузка ограничена 10 секундами.
Уход курсора возвращает первый кадр; размонтирование отменяет таймер и
игнорирует поздние результаты. Один кадр не создаёт таймер.
На странице статьи первый кадр статичен; fallback — cover_image.
Если обоих нет, сохранён прежний редакционный ArticleSlider.

Запрос начинается при приближении карточки к viewport на 200px.
Promise кешируется по slug+lang на время работы страницы, включая ошибки и пустые
результаты; повторить неудачный API запрос можно перезагрузкой страницы.
При смене языка карточка перемонтируется, поздние результаты старого языка игнорируются.
Только первый кадр загружается до hover; остальные — по одному во время воспроизведения.
Touch/coarse pointer и prefers-reduced-motion отключают hover через matchMedia.
Карточка остаётся обычной ссылкой, открываемой клавиатурой. CSS и размеры не менялись.

## Конфигурация и оставшиеся ручные проверки

Обязательная для минералов: VITE_CDN_BASE_URL=https://lithoteka-cdn.storage.yandexcloud.net.
Существующие VITE_API_BASE_URL (опциональный адрес API) и API_PROXY_TARGET
(локальная цель Vite proxy) сохраняют своё назначение. Новых переменных для кадров нет.

На работающем API с наполненными последовательностями проверить:
1. RU/EN, быстрые смены языка и отсутствие смешивания кадров.
2. Hover 700 мс, цикл, уход курсора, один кадр, 404 изображения и fallback cover_image.
3. Touch, reduced-motion, открытие ссылки клавиатурой и отсутствие скачков размеров.
4. Медленную сеть, уход со страницы во время загрузки, большую страницу карточек.
5. Hero и gallery сущности с различными slug и storage_key.
6. Markdown иллюстрации, пары и языковые overrides на реальных статьях.

Ограничение данных: у текущей опубликованной quartz нет кадров ни RU, ни EN,
поэтому живую hover-анимацию пока проверить невозможно без наполненных данных.
Старых жёстко заданных адресов бакета в src/public не найдено.
Общие изображения главного слайдера локальные. Их соответствие объектам
common_images неизвестно; пути не придумывались и изображения не переносились.
